## 一、核心立足点实证：`step5_3` + `step5_1` + `CP-uniGuard` 源码核查

### 1.1 文献源码核查：`CP-uniGuard` (arXiv:2506.22890)
- 经核实官方源码 `adaptive_threshold.py`（L42–46, L110–126）与 `cp_uniguard.py`（L439）：其 `OnlineAdaptiveThreshold` 是按时间/场景整体双滑窗更新的**单一全局标量门限**（仅叠加递归深度微小偏置 `gamma = 0.02`），**完全不按单车或传感器类型分档**。

### 1.2 现有防御在干净 Dev-320 上的跨模态失衡（实验 A）
1. **`HetShield`（修复版 64ch ConvGRU，统一判据）**：
   - **干净异常分分布**：诚实 `m1` 均值 `0.171`（`p95 = 0.297`，`max = 0.347`）；诚实 `m2` 均值 **`0.379`**（`p95 = 0.438`，`max = 0.482`）。根因拆解：跨模态一致性 `sigma_k` 上 `m1 = 0.881`，而 `m2` 仅 `0.390`。
   - **原论文统一门限 `τ = 0.3`**：诚实 `m1` 误报 `4.06%`，诚实 `m2` 误报 **`98.75%`**（差值 **`+94.69%`**，`95% CI [+84.77%, +99.13%]`，统计显著）。
   - **放宽统一门限后**（等 5% 总 FPR `τ = 0.424` 或压低 `m2 ≤ 5%` `τ = 0.438`）：攻击者为 `m1` 时，3 类攻击（`Global PGD 1.0σ` / 定向目标移除 / 虚假目标伪造）的检出率全部暴跌至 **`0.00%`**（尽管 `m1` 单模态 PGD AUROC 为 `0.7817`，全被统一门限扼杀）。
   - *注：在 FIT-11 标定集（`step5_1`）上呈现同样鸿沟：Shared 诚实 `m2` 中位数 `0.592` 高于诚实 `m1` 的 `p99 (0.514)`；即便各自独立训练 PerSensor ConvGRU，诚实 `m2 p95 = 0.885` 仍为诚实 `m1 p95 = 0.226` 的近 4 倍。*
2. **`LUCIA` (USENIX Security'25)**：
   - 2 车干净 L1 距离：诚实 `m1` 均值 `21.85`，诚实 `m2` 高达 **`54.17`**（`2.5×`）；
   - 混合多车队（≥3 车，同帧对比）：诚实 `m1`（`n = 362`）信任分均值 **`0.974`**（中位数 **`1.000`**），诚实 `m2`（`n = 440`）信任分腰斩至均值 **`0.394`**（中位数仅 **`0.155`**）。
3. **`ROBOSAC` (ICCV'23，≥3 车干净 279 帧)**：官方保守门限 `0.3` 下误拒率为 `0.0%`；收紧至 `0.5` 时混合车队误拒率升至 **`15.41%`**（高于纯 `all_m1` 的 `12.55%`）。

## A 阶段：代码 bug 修复（P0，12/8 前完成）

### A1 可见性统计表不一致（真 bug）
- **问题**：`step4_1` 生成的分档归一化统计表（按"传感器 × 5 个距离档 × 3 个可见性档"统计 median 与 p95）使用的是**旧版** σ_alea 可见性（阈值 0.33 / 0.67，见 `step4_1_v2_core.py:300-303, 394`）。而 `step4_4` / `step4_5` 查表时用的是**新版** ℓ / N_exp 可见性（`assign_dist5_vis3_indices_v2`）。两边的分档定义不一致。
- **做法**：
  1. 统计表改用 `assign_dist5_vis3_indices_v2` 计算的可见性（`clear_pts_tau` 和 `los_occ_tau` 与 step4_4 保持一致），在 Fit 的 100 帧上重新统计；
  2. 依次重跑 step4_4 标定和 step4_5 Dev 评测。
- **验收**：给出标准指标的前后对比；`v_idx` 的来源全仓库只剩一个函数。

### A2 HetShield 按原论文复现
- **问题**：
  1. 原论文 α = 0.6，代码是 0.5；
  2. 原论文是把协作车特征按 g_k **往本车特征方向混合**（z̃_k = g_k·z_k + (1−g_k)·z_0），代码是缩放融合权重；
  3. 标定（step5_1）时连续跑整条序列，被隔离后隐状态不再更新，导致 p95 被抬高，而且标定协议和评测协议（每帧清零 + 预热一步）不一致；
  4. `step5_1:225` 传进去的是 `enumerate` 的序号，不是真实帧号 `idx_v`。
- **做法**：
  - 按原文改 α 和混合方式。请先重读 arXiv:2609.17856 的 HetShield 一节，确认公式与默认参数：τ_gate = 0.3，T = 0.1，α = 0.6。
  - 标定和评测统一为同一协议：每帧先 `reset_sequence`，用前一帧以 `update_state=True` 预热一步，再在当前帧上以 `update_state=False` 打分。
  - 帧号改用 `idx_v`。
  - 重新标定 Tuned（全局）和 PerSensor（分传感器）阈值。
- **额外输出**（论文表 2 要用）：
  - 诚实 m1 / m2 协作车的 g_k < 0.5 比例；
  - 时间项 τ_k 和空间项 σ_k 各自的分布（均值、p50、p95）；
  - HetShield 在 m1+m2 干净场景下的盲区 AP。这一项用来和原论文报告的"精度恢复"对照，如果两者矛盾，需要写一段原因分析。

### A3 测试集锁与 ASR 纳入终测
- step8 的 `final_test_once` **一开始**就写入 `FINAL_TEST_STARTED.json`，如果这个文件已经存在就拒绝运行。
- 把 step5_4（ASR）加进 `final_test_once` 的子进程列表。
- 输出所有被冻结参数的完整 JSON 快照，论文的参数表直接从这个文件读取。

### A4 指标修改（防止被审稿人质疑"指标可以刷"）
- **ASR**：
  - 只把分数 ≥ s_min 的框算作"有检测"。s_min 取 HEAL 后处理的默认分数阈值，并在 JSON 里写明具体数值；
  - **伪造**：如果锚点 3 m 内本来就有真值框，这个锚点不计入分母；
  - **移除**：只统计无攻击时能检测到的目标（现有逻辑保留）；
  - 每个 ASR 都要和同一方法的干净 AP 一起报告。
- **盲区 AP**：只用盲区真值框（满足：位于协作车覆盖区内、本车 LiDAR 点 ≤ 5、不是本车自身）计算 AP@0.5。现有的盲区召回保留，放进附表。
- **诚实协作车被压制比例**：在干净数据上，统计每辆诚实协作车覆盖区内 G_i < 0.5 的格子比例，按传感器 × 可见性分档报告。整车回退记为 100%。

### A5 标定数据和调参数据按序列分开（审稿人 3 的意见）
- 现状：用来挑 Dev 参数的 36 帧带攻击数据，是 100 帧标定数据的子集，两者重叠。
- 改为：Fit 的 11 条序列分成两组，**7 条用于标定**（μ_l、s_l、Q、Q_frame、τ_N 等统计量），**4 条用于挑选 Dev 参数**（网格搜索）。两组不共享任何序列。
- 记录网格搜索的范围、目标函数和尝试过的配置数（论文要写）。
- 输出每个标定分档（传感器 × 距离 × 可见性 × 前景/背景）对应的格子数、帧数、序列数，并对每个阈值 Q 做序列级 bootstrap，给出 95% 置信区间。样本太少的分档（例如帧数 < 20）向上一级合并（例如去掉距离维），并在 JSON 里注明。

## B 阶段：方法修复（P0，12/15 前完成，每项单独在 Dev 上验证）

> 顺序：B1 → B2 → B3 → B4。每完成一项，在 Dev 上跑一遍标准指标，修复后不变差才保留。

### B1 粗尺度门控取最小值
- `bud_fusion_heal.py:260`：把 `F.interpolate(g_src, size=(h,w), mode="area")` 改为 `-F.max_pool2d(-g_src, kernel_size=s, stride=s)`，其中 s = 256 / h（L1 为 2，L2 为 4）。
- **验收**：三种局部攻击的 ASR 不升，干净 AP 下降不超过 0.5。

### B2 前景判定以本车为准
- 现状：`fg = MaxPool3x3(p_{0,i}) > 0.2`（只看协作车）。
- 改为：
  ```
  fg = (MaxPool3x3(p_0) > 0.2) | ((MaxPool3x3(p_{0,i}) > 0.2) & (v != Clear))
  ```
- `step4_4` 标定、`step4_5`、`step5_2`、`step5_4` 中所有构造 `fg_mask` / `collab_fg_mask` 的地方都要同步修改。**标定时也必须使用这条新规则**，用旧规则标定、新规则部署会导致不一致。
- **验收**：局部伪造和遮挡区伪造的 ASR 下降；干净盲区 AP 下降不超过 1 个点。

### B3 被削减的权重只分给"其他"可信车（第三版，必须按这个实现）
- `bud_fusion_heal.py:263-269` 现在是把被削减的权重全部还给本车。
- **改为**（逐格子、逐尺度 l 计算；G_0 ≡ 1）：
  ```
  T      = {0} ∪ {j ≥ 1 : G_j ≥ 0.9}                     # 可信集合
  R_i    = (1 − G_i) · ω_i              (i ≥ 1)          # 协作车 i 被削减的权重
  T_{-i} = T \ {i}                                       # 不包括 i 自己
  ω̃_j   = G_j·ω_j + 1[j∈T] · Σ_{i≥1, i≠j} R_i · ω_j / Σ_{k∈T_{-i}} ω_k
  # 如果 Σ_{k∈T_{-i}} ω_k = 0，则 R_i 全部加给本车 ω̃_0
  ```
- **严禁**两种错误写法：
  - (a) `G_i·ω_i / Σ_j G_j·ω_j`（对所有车重新归一化）：在只有攻击者覆盖的格子上，攻击者的权重会被恢复成 1；
  - (b) 把所有车被削减的权重合成一个总量 R，再分给整个可信集合 T：门控值在 0.9–1 之间的车会把自己被削减的权重又拿回去，而且只有一辆协作车时和原实现不一致。
- **单元测试**（必须写，全部通过才能合并）：
  1. 所有 G = 1 时，ω̃ = ω；
  2. 只有攻击者覆盖、G_a = 0.1 的格子，ω̃_a = 0.1·ω_a，其余权重全部归本车；
  3. 每个格子上 Σ ω̃ = Σ ω（权重总量守恒）；
  4. 只有一辆协作车时，**不论 G_1 取值多少**（包括 0.95），结果都与"全部还给本车"的原实现完全一致；
  5. 两辆协作车，G_1 = 0.95、G_2 = 0.2 时，协作车 2 被削减的权重按 ω_0 : ω_1 的比例分给本车和协作车 1；协作车 1 自己被削减的 0.05·ω_1 只分给本车，不能回到它自己。
- **验收**：≥3 辆协作车时的干净 AP 下降缩小（原来约 −4 个点）；"两个攻击者"场景的 ASR 不升。

### B4 遮挡区新增权重 γ(Occluded) 的取舍（只做分析，不强制修改）
- 在 Dev 上扫描 γ(Occluded) ∈ {0, 0.1, 0.2, 0.3}，报告"遮挡区伪造 ASR"和"干净盲区 AP"之间的权衡曲线。
- 默认保持 0。如果 0.1 能让 ASR 明显下降，而盲区 AP 降幅不超过 0.5 个点，就改为 0.1。

### D5（P1）RQ5：自适应攻击（审稿重点，务必做扎实）
总体要求：
- 攻击者知道 BUD 的全部参数和标定表；
- 步数扫描 {20, 50, 100}，确认攻击已经收敛；
- 加 1 次随机初始化重启；
- 报告"BUD 下的 ASR"和"同一扰动在无防御下的 ASR"。如果后者也随之下降，说明攻击者为了躲避检测，不得不削弱攻击。

1. **门控感知 PGD（端到端）**
   - 把 BUD 的门控计算改写成可微版本：
     - cos、z 归一化（统计表与 v、b 只依赖本车和距离，对攻击者来说是常数，可以预先算好索引图）；
     - max/avg pool；
     - [·]₊ 用 ReLU；
     - p_{0,i} 通过两两融合前向得到，本身可微；
     - 整车回退的硬阈值改成 `sigmoid((s_i − τ_high)/0.05)`。
   - 两种写法都要做：
     - (a) 惩罚式：`L_atk(无防御融合) + μ·Σ E_i`，μ ∈ {0, 0.1, 1, 10}；
     - (b) 端到端式：直接对"经过 BUD 门控后的融合输出"优化 L_atk。
   - ε ∈ {0.5, 1, 2}σ。
2. **专挑宽松条件的攻击**：
   - 把扰动区域限制在 v ∈ {Sparse, Occluded} 或距协作车 ≥ 30 m 的格子；
   - 伪造目标也选在这些格子里；
   - ASR 按可见性分档报告。
3. **幅度攻击**：
   - 把攻击者特征整体缩放 s ∈ {0.5, 0.8, 1.2, 1.5, 2}（在 ε 允许范围内，再加一组不受 ε 限制的）；
   - 报告门控和整车回退的检出率，以及对检测结果的影响。
   - 如果这类攻击能明显绕过检测，追加任务 B5：增加范数偏差通道 |log(‖Z_i‖/‖Z_0‖)|，同样按条件归一化，在 Dev 上验证后再决定是否纳入。
4. **两两融合看起来正常的攻击**（≥3 辆协作车）：攻击损失在 N 车完整融合上计算，同时惩罚**两两融合**下算出的 E_i。目的是检验"用两两融合做审计"会不会被绕过。
5. **谎报传感器类型**：m1 攻击者使用 m2 的标定表（Q、μ、s 全部换成 m2 的），再跑局部攻击和门控感知 PGD，与如实声明类型时的结果对比。

   - 全覆盖区低强度扰动，强度刚好压在门控阈值之下；
   - 真值框平移 1–3 m（指标用定位误差和 AP@0.7）；
   - **第三方盲区移除**（≥3 辆车）：攻击者去抹掉一个只有另一辆诚实协作车看得到、本车看不到的目标。
6. **自适应攻击加强**（D5 的升级版）：
   - 端到端优化，5 次随机重启，最多 100 步，并画出攻击损失随迭代的收敛曲线；
   - 不可导的部分（前景判定、可信集合判定、整车回退）一律用 sigmoid 近似，反向传播用直通（BPDA）；
   - 做一次无梯度的 Square Attack 检查，排除梯度掩蔽；
   - 健全性检查：取消 ε 限制后，ASR 应接近 100%；
   - 新增**共谋攻击**：两个攻击者，一个故意被门控，另一个保持可信（G ≥ 0.9）去接收被削减的权重；
   - 新增**占用分数抬高攻击**：攻击者抬高自己的占用分数，试图压低诚实车的融合权重；
   - 论文的标题数字取所有自适应攻击中的最坏情况。
7. **位姿噪声与通信延迟**：使用 HEAL 自带的噪声设置（0.2 m / 0.2°，延迟 100 ms）。分两组：(a) 用干净数据标定，在带噪声的数据上测试；(b) 用带噪声的数据标定，在带噪声的数据上测试。报告诚实压制比例、干净 AP、盲区 AP 和局部攻击的 ASR。审稿人 2 明确说：如果有噪声时诚实压制比例大幅上升，论文会被拒。
8. **指标细节**：
   - 盲区 AP 中，匹配到非盲区真值的预测记为"不计分"；另外报告"协作车自己确实看得到的盲区目标"子集；
   - 诚实压制除了 G < 0.5 的比例，再报告被削减的权重占比 Σ(1−G)ω / Σω；
   - 锚点 3 m 内有真值框的伪造，单独作为"近目标伪造"报告，不要直接丢掉；
   - ASR 对检测分数阈值 s_det 的敏感性（扫 3 个取值）。
9. **统计方法**：
   - 4 个主要终点：(1) 干净 AP 非劣于无防御，容许差 1 个点；(2) 盲区 AP 保留率；(3) 局部攻击 ASR 相对最强基线的降幅；(4) 所有自适应攻击中的最坏 ASR；
   - 用序列级配对的 studentized bootstrap，4 个主要终点做 Holm 校正；
   - 报告每个分层的序列数。
